# FE-10 (= OPS-1) · fix the 3 stale browser tests; stable test hooks

**Owner:** ui-builder · **Reviewer:** ui-reviewer (markup changes) · **Skills:** `dashboard-design`, `engineering:testing-strategy` · **Size:** S (about 10 template lines, 20 test lines)
**Planned 2026-11-04 (plan only; nothing changed yet).**

## Understanding
Three browser tests hardcode demo counts or read only the chips a tile shows by default, and the universe grew from 60 to 348
stocks. Derive every expected value from the page's own `DATA` and live counts, open "+N more" before reading tile chips, and add
a few `data-testid` / `data-k` attributes so tests stop depending on DOM position. No payload field changes.

## Confirmed causes (`pytest tests/test_browser.py -q`: 3 failed, 15 passed)
- Row count: 60 is stale (348 rows, 55 dips). Nordic: 18 is stale (34).
- "New since yesterday" tile: **only the cap of 8 chips, no real mismatch.** After "+12 more" there are 17 chips, the tile says 17
  and 17 rows carry NEW: the same set. At 390 px the chips are hidden by design, so the test stays at desktop width.

## Steps
1. `src/template.html`, attributes only (no visual change): tiles get `data-testid="tile-quality|new|knife|market"` (the `mk`
   helper takes an id), chips `tile-chip`, the "+N more" button `tile-chip-more`, the NEW badge `new-badge`, and every table cell
   `data-k=<column>` matching the header's existing `data-k`.
2. `tests/test_browser.py` changes below. 3. Browser suite, 4 screenshots compared with the previous set, axe. 4. One commit.

## Test changes (old → new)
- `SHOWN` helper: read `tr.dataset.t` and `[data-testid=new-badge]` instead of `.tkbtn` childNodes.
- Row count: `== 60` → `== DATA.rows.length`, and the "All stocks" button count equals it too.
- Quality-dip count: also equals the number of rank-4 rows and the quality tile's number.
- Nordic: `== 18` → `== DATA.rows.filter(region === 'Nordic').length`, and between 0 and the total.
- New-since-yesterday: click "+N more" if present, read all chips, assert chips = tile number = rows marked NEW (and > 0).
- Price sort: `td:nth-child(2)` → `td[data-k=price]`.

## Verification
- `pytest tests/test_browser.py -q` → 18 passed; full suite otherwise unchanged.
- 4 screenshots (demo; 1280/390; light/dark) show no visual difference; axe 0 violations; no console errors.
- Mutation check by hand, reverted: removing the NEW badge makes the test fail.

## Risks
Expected values taken from `DATA` can hide a payload bug (page and test agree with each other); the Python-rule parity test and
OPS-5's contract test cover that. `template.html` is in the hot group, so no other wave-1 task touches it during this one.
