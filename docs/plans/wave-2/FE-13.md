# FE-13 · visual-regression screenshots and `docs/frontend-contract.md`

**Owner:** ui-builder · **Reviewer:** ui-reviewer, test-engineer (new `tests/visual/`, CI) · **Skills:** `dashboard-design`, `engineering:testing-strategy` · **Size:** M
**Planned 2026-11-04 (plan only). Starts after FE-3-4-7** (needs the stale state and stable hooks). Not in the hot group once the template is quiet.

## Understanding
Today `scripts/screenshots.py` renders four PNGs and checks console errors and overflow, but nothing compares them. Add named UI
states, deterministic rendering, and a pixel diff against committed baselines, so a colour or layout change is flagged. Also write the
contract listing every DOM id and `data-*` hook that tests depend on.

## States (each at 1280 and 390, light and dark = 4 shots per state)
default, detail open (first row), filters changed (Window 1 day, min drop 3, Nordic), empty (search "zzzz"), stale (fake clock), print (`emulate_media(media='print')`), failure (broken row).
That is 7 x 4 = 28 PNGs. **Q1 size.** (a) all 28 (about 2-4 MB with palette PNG); (b) light only for secondary states, 16 shots; (c) **recommended:** (a) for default/detail, light-only for the rest: 12 shots.

## Determinism (required or the diff is noise)
- Fixed demo build (seeded, `--demo`), fixed viewport and `device_scale_factor=1`, `page.clock.set_fixed_time`, `animations='disabled'`,
  `reduced_motion='reduce'`, caret hidden. Route `**/fonts.googleapis.com/**` and `fonts.gstatic.com` to empty and pin fonts.
- **Q2 fonts.** (a) system fallback fonts (differs per OS, so baselines only valid on one machine); (b) **recommended:** bundle one
  woff2 file locally for tests only via `page.add_style_tag` (no new dependency; license check); (c) accept a looser threshold.
- Baselines are generated in the cloud container (Linux Chromium); Iiro's Windows run is told to skip the diff (`DIP_VISUAL=0`) or use `--update`.

## Diff method
- `Pillow` + `numpy` (numpy exists; **Pillow** needed: one line reason, it decodes PNGs for pixel compare; alternative `pixelmatch` is a second dependency).
  Q3: (a) exact match; (b) **recommended:** per-pixel tolerance 8/255 and fail above 0.1% changed pixels, writes `*.diff.png` and `*.actual.png` to `output/visual/`; (c) perceptual hash, too coarse.
- `python scripts/screenshots.py --states all --compare tests/visual/baseline` ; `--update` rewrites baselines (never in CI).
- `tests/visual/test_visual.py` parametrised over states, skipped if no Chromium or Pillow, like `test_browser.py`.

## `docs/frontend-contract.md`
A table: hook (id, `data-testid`, `data-k`, `data-t`, class) -> who uses it (test or script) -> meaning. Includes `tile-*`, `tile-chip`, `tile-chip-more`,
`new-badge`, `stale`, `cards-more`, `dqbtn`, `dqpanel`, `body`, `head`, `show`, `region`, `q`, and the `DATA` fields the page reads (link to `docs/payload.md`, do not copy it).
Rule: change a listed hook only with the test in the same commit. **Q4 enforcement.** (a) prose only; (b) **recommended:** a test that greps the contract for each hook and
asserts it exists in `src/template.html`, and the reverse for hooks used in tests; (c) generate the page from the contract (too heavy).

## Verification
- Planted colour change (`--down` hue shift, reverted) fails the compare with a diff image; an unchanged rerun passes twice in a row (no flake).
- Baselines looked at by eye once (Rule 2), axe and overflow checks still run.

## Risks and requests
- Baselines are an architectural lock-in: a deliberate design change needs `--update` and a reviewer look at the diff. Documented in the contract.
- `.gitignore`/ownership: the orchestrator adds `tests/visual/**` (ui-builder) and Pillow to `requirements-dev.txt` (test-engineer).
